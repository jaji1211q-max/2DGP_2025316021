# Animation Viewer 개발 기획

## 목표

`animation_viewer.py`에서 `sprites_fullsize.png`를 사용해 800x800 화면 중앙에 크게 캐릭터를 표시한다. 화면 왼쪽에서 출발해 중앙까지 오른쪽으로 달리고, 중앙에서 점프와 공격을 한 뒤 왼쪽 시작 위치로 달려 돌아오는 동작을 끊임없이 반복한다. 이동 방향에 맞춰 좌우를 바라보게 하고, 창 닫기 또는 `ESC` 입력으로 종료할 수 있게 한다.

## 스프라이트 시트 조사

- 파일: `sprites_fullsize.png` (544x416, RGBA)
- 시트에서 관찰한 기본 프레임 영역은 32x48 픽셀이다.
- 첫 번째 애니메이션 행은 `y=0`, `x=16..496`에서 32픽셀 간격으로 16프레임을 읽을 수 있다. 셀 시작점은 x=16 오프셋이며, 좌우 이동에 공통으로 사용하고 진행 방향에 따라 수평 반전한다.
- 점프 후보 프레임은 `y=96` 행의 `x=160, 192, 224`이다.
- 공격 프레임은 스프라이트 시트에서 아래에서 두 번째로 보이는 행의 첫 네 동작이다. 투명 여백을 제외한 각 프레임의 픽셀 경계에 맞춰 개별 클립 영역을 지정한다.
- 프레임 영역은 코드 상수로 모으고, 이미지 경계 안에 있는지 테스트한다. 후보 프레임이 의도한 동작과 다르면 시트 미리보기로 확인한 좌표를 기획 문서와 코드에 함께 반영한다.

## 동작 및 화면

- 캔버스: 800x800
- 캐릭터 렌더 크기: 기본 32x48 프레임보다 크게 확대해 화면 중앙을 차지하도록 한다.
- 시작점: 화면 왼쪽 안쪽
- 진행 순서: 오른쪽 달리기 → 중앙 도착 → 점프 → 공격 → 왼쪽 달리기 → 시작점 복귀
- 모든 이동은 프레임마다 일정 시간 대기하는 방식 대신 경과 시간 기반으로 처리해 속도를 일정하게 유지한다.
- Pico2D 이벤트를 매 프레임 처리하고 창은 한 번만 열고 종료 시 닫는다.

## 검증 기준

- 선택한 모든 프레임 직사각형이 544x416 시트 경계를 벗어나지 않는다.
- 뷰어 모듈을 import해도 창이 자동으로 열리지 않는다.
- 방향 상태가 오른쪽 진행 때 오른쪽, 왼쪽 복귀 때 왼쪽을 바라보게 한다.
- 중앙에서 점프와 공격을 차례대로 한 번씩 실행한 뒤 왼쪽 시작점으로 돌아온다.
- 사이클은 창이 열려 있는 동안 반복되며, `ESC`와 창 닫기 모두 정상 종료한다.
- 화면은 800x800이고 확대된 캐릭터는 화면 중앙의 동작 구역 안에서 잘리지 않는다.

## 구현 결과

- `animation_viewer.py`는 스크립트와 같은 폴더의 스프라이트·잔디 이미지를 불러온다. 스프라이트는 8배 확대하고, x=160에서 시작해 x=400에서 점프·공격한 뒤 다시 x=160으로 돌아온다.
- 셀의 실제 x 원점은 16픽셀이다. walk 프레임은 `x=16..496, y=0`, jump 후보는 `(160,96), (192,96), (224,96)`이다. 공격은 아래에서 두 번째 행의 첫 네 동작을 사용하며, 프레임 너비가 다르므로 각 프레임을 별도 폭으로 자른다.
- 알파 채널을 기준으로 각 선택 프레임이 비어 있지 않고 시트 경계 안에 들어오는지 확인했다.
- 단위 테스트 실행: LEC08 폴더에서 `python -m unittest test_animation_viewer.py`
- 10개 테스트에서 시작 경로, 좌우 반전, 프레임 경계, 점프 궤적, 반복 상태 전이를 확인한다.
- 20개가 넘는 단계별 커밋을 만들고 각 커밋을 GitHub `main`에 푸시했다.
